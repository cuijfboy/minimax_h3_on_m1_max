### 实施中发现的技术细节

**1. `ConcatenateVideo` 的输入命名**

`videos` 是 `COMFY_AUTOGROW_V3`，**实际展开名是 `videos.video0` / `videos.video1` / `videos.video2`**（不是 `video`、`video0` 等）。

这是实测探明的 —— 源码里 `f"{prefix}{i}"` 和注释里"prefix gets added in parse_class_inputs" 两处线索都不够明确，最后靠**逐个提交探测**才确定。

**2. `ImageFromBatch` 支持负索引** ✅

~~~python
if batch_index < 0:
    batch_index += s_in.shape[0]
~~~

所以 `batch_index = -1` 就是"取最后一帧"，不用手动算帧数。

**3. 三镜串联的实际耗时是可接受的**

471 秒完成"3 次生成 + 2 次接力 + 1 次拼接"，说明**流水线本身开销很小**，瓶颈只在单镜生成。

### ✅ 路线 B 实施结果：自研两个节点

新增自定义节点包 `ComfyUI/custom_nodes/h3-toolkit/`（`nodes.py` 89 行 + `__init__.py`）：

| 节点 | 作用 |
|---|---|
| `H3StructuredPrompt` | 场景/动作/镜头/风格/音效 五字段 → 一段提示词；留空字段自动跳过，音效单独成段 |

**效果**：分镜工作流 **15 节点 → 13 节点**；更重要的是提示词从"一大段"变成**结构化五字段**。

**验证**：
- 节点注册成功（972 → **974**）
- 拼接逻辑单测通过（五字段 / 单字段 / 全空 / 无音效 四种情况）
- 接力实测通过（66 帧 = 22×3，视觉无缝）

### ✅ 分镜工作流优化（原遗留问题 1、4）

| 项 | 改前 | 改后 |

| 提示词 | 3 个单文本框 | **3 个 H3StructuredPrompt（各 5 字段）** |

**优化后的正式验收**（192 + 124 + 124 = 440 帧，全程 864×480）：

| 项 | 结果 |
|---|---|
| **总耗时** | **5461 秒（91.0 分钟）** |

| 拼接成片 | **440 帧** = 192+124+124 ✅ / **18.33 秒** |

**叙事验收**：大远景（横摇展示远山与脚印）→ 中景跟拍（狐狸变大、金色长影）→ 特写（狐狸抬头仰望）。

**建立镜头 8 秒的价值得到验证** —— 124 帧时观众还没看清环境就切走了，192 帧才有时间横摇铺陈。

## 4. 关键技术验证（已实测确认）

### 4.1 ⭐ 末帧接力链路

**所需节点全部存在**（已通过 `object_info` 逐一确认）：

```
WildH3_1 ──VIDEO──▶ GetVideoComponents ──IMAGE──▶ ImageFromBatch
                                                      batch_index = 末帧
                                                      length = 1
                                                          │
                                                          ▼ IMAGE
                                                    WildH3_2.first_frame
```

| 节点 | 输入 | 输出 |
|---|---|---|
| `GetVideoComponents` | `video` | `images`, `audio`, `fps`, `bit_depth`, `color_space` |
| `ImageFromBatch` | `image`, `batch_index`, `length` | `IMAGE` |

**这意味着 H3 Studio 的"末帧接力"可以在 ComfyUI 里用连线实现。** ✅

### 4.2 ⭐ 多镜头拼接

`ConcatenateVideo` 是 ComfyUI **原生节点**：

| 项 | 值 |
|---|---|
| 输入 | `videos` — **`COMFY_AUTOGROW_V3`**，min 1 / **max 100** |
| 可选 | `complete_audio`（覆盖音轨） |
| 输出 | `VIDEO` |
| 说明 | "Video segments to concatenate in input order" |

**autogrow 输入意味着可以接任意段数**（1–100），不用改节点结构。✅

### 4.3 动态 UI 的可行性

ComfyUI 前端扩展 API（已在静态资源中确认存在）：

| API | 出现文件数 | 用途 |
|---|---|---|
| `registerExtension` | 12 | 扩展入口 |
| `extensionManager` | 4 | 管理器 |
| `registerSidebarTab` | 1 | **添加侧栏面板** ✅ |
| `registerBottomPanelTab` | 1 | 添加底部面板 |

自定义节点可通过 `WEB_DIRECTORY` 附带前端 JS（`nodes.py:2297` 有此机制）。

**→ 技术上可以做一个"分镜板"侧栏面板，但这是真正的前端开发工作量。**

## 5. 三条路线（按投入排序）

### 🟢 路线 A：零代码 —— 静态多镜工作流（**推荐先做**）

**做法**：做一张 `h3-storyboard-3shot.json`，3 个 Wild H3 节点串联：

```
[提示词1] ─▶ WildH3_1 ─┬─▶ ConcatenateVideo ─▶ SaveVideo
                       │         ▲
        末帧接力 ───────┘         │
                                │
[提示词2] ─▶ WildH3_2 ──────────┤
                       │         │
        末帧接力 ───────┘         │
                                │
[提示词3] ─▶ WildH3_3 ──────────┘
```

| 项 | 说明 |
|---|---|
| **优点** | **不写任何代码**，纯连线；用现有全部节点 |
| **缺点** | 镜头数固定为 3；改镜头数要动图 |
| **工作量** | 约 **1 小时**（建图 + 实测） |
| **覆盖度** | 约 **80%** 的多镜头需求 |

### 🟡 路线 B：小量代码 —— 自研 2–3 个辅助节点

| 节点 | 作用 |
|---|---|
| `H3StructuredPrompt` | 5 字段（场景/动作/镜头/风格/音效）自动拼成一段 |
| `H3LastFrame` | 把 `GetVideoComponents` + `ImageFromBatch` 封成一个节点 |

| 项 | 说明 |
|---|---|
| **优点** | 工作流更简洁，结构化提示词可用 |
| **工作量** | 约 **2–3 小时** |

### 🔴 路线 C：完整融合 —— 开发 ComfyUI 侧栏分镜面板

用 `registerSidebarTab` + `WEB_DIRECTORY` 做一个真正的分镜板：

- 动态增删镜头
- Take 选择与对比
- 参考集管理
- 一键拼接

| 项 | 说明 |
|---|---|
| **优点** | 功能上完全替代 H3 Studio |
| **缺点** | 前端 React 开发 + 后端 API，工作量大 |
| **工作量** | 约 **2–3 天** |
| **风险** | ComfyUI 前端 API 版本变动（当前 frontendVersion 1.53.x） |

## 6. 建议

### 6.1 推荐的推进顺序

```
路线 A（1 小时）  ──▶  验证多镜头在 ComfyUI 的可行性
       │
       ▼
   看实际体验，再决定
       │
       ├──▶ 路线 B（2–3 小时）如果嫌连线繁琐
       │
       └──▶ 路线 C（2–3 天）如果要做成产品级
```

### 6.2 ⚠️ H3 Studio 暂不退役

**断点续跑**是它独有的能力，而这一点对长任务很重要：

| 场景 | 为什么需要 |
|---|---|
| 92 分钟的视频生成 | 跑到一半发现构图不对，可暂停看草稿 |
| 多镜头批量 | 中途改主意，不必从头再来 |

ComfyUI 的图是**原子执行**的，中途无法保存/恢复。所以：

> **建议**：ComfyUI 作为日常主界面，H3 Studio 保留给"要断点续跑的长任务"。

### 6.3 不建议做的事

| 不建议 | 原因 |
|---|---|
| 现在就上路线 C | 投入 2–3 天，但路线 A 已能覆盖 80% 需求 |
| 一次性串联太多镜头 | 3 镜 = 276 分钟，失败代价太高 |

## 7. 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| **串联后单次跑太久**（3 镜 = 276 分钟） | 🟠 中 | 先用 `h3-local-draft`（23 分钟/镜）验证分镜，再跑成品 |
| 末帧接力画质损失 | 🟡 低 | 需实测；h3.c 支持首尾帧，理论上衔接自然 |
| `ImageFromBatch` 负索引行为 | 🟡 低 | 实测确认；不行就传"总帧数-1" |
| ComfyUI 前端 API 变动 | 🟡 低 | 只影响路线 C |
| 断点续跑无法替代 | 🟠 中 | 保留 H3 Studio |
