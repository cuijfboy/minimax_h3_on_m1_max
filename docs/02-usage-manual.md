# MiniMax H3 使用手册（GUI 版 · 手把手）

> 本机已部署完成的 MiniMax H3 全链路使用指南 · **以图形界面为主**
> 机器：Apple M1 Max 32GB · macOS 27
> 看不明白某一步？第 3 章是**手把手演练**，照着点就行。

---

## 0. 一页速查

| 我想做什么 | 打开 | 怎么做 | 耗时 | 成本 |
|---|---|---|---|---|
| **文生图 · 概念图/配图** ⭐ | ComfyUI http://127.0.0.1:8188 | 打开 `image-t2i-turbo` → 写提示词 → Run | **7 分钟 / 4 张** | 免费 |
| **配图放大到 2K** ⭐ | ComfyUI | 打开 `image-upscale-2k` → 选图 → Run | **2 秒** | 免费 |
| **图 → 视频** ⭐ | ComfyUI | 打开 `image-to-video` → 写两个提示词 → Run | 约 95 分钟 | 2K 费 |
| **三镜短片** ⭐ | ComfyUI | 打开 `h3-storyboard-3shot` → 写三段提示词 → Run | 约 69 分钟 | 免费 |
| **日常出片**（最常用） | ComfyUI | 打开 `h3-local-quality` → 改提示词 → Run | 92 分钟 | 免费 |
| **快速试想法** | ComfyUI | 打开 `h3-local-draft` → 改提示词 → Run | 23 分钟 | 免费 |
| **一句话出 2K** | ComfyUI | 打开 `h3-full-chain` → 写中文想法 → Run | 约 100 分钟 | $0.02 + 2K 费 |
| **多镜头（>3 镜/要续跑）** | H3 Studio http://127.0.0.1:3000 | 分镜板 → 添加镜头 → 末帧接力 | — | 免费 |
| **批量/自动化** | 终端 | `./h3gen` / `./comfy-contextir` / `./comfy-2k` | — | 同上 |

**核心记忆点**：**一个主界面 + 八张预置工作流**。日常只用 ComfyUI；H3 Studio 仅在需要断点续跑时用。

> 🔑 **最优工作流**：先用文生图（7 分钟）把画面定下来 → 再接图生视频（95 分钟）。
> 比直接"文字碰运气跑 92 分钟"靠谱得多。

## 1. 系统总览

### 1.1 它们分别是什么

~~~
┌──────────────────────────────────────────────────────────┐
│              ComfyUI  ← 主界面（日常都用这个）              │
│              http://127.0.0.1:8188                        │
│                                                          │
│  三张预置工作流（打开就能用，不用自己连线）：                  │
│   ┌────────────────┐ ┌─────────────────┐ ┌─────────────┐ │
│   │ h3-local-draft │ │ h3-local-quality│ │h3-full-chain│ │
│   │  23分钟 / 免费  │ │   92分钟 / 免费  │ │100分/约$0.02 │ │
│   │   864×480      │ │    1344×768     │ │  →  2K      │ │
│   └────────────────┘ └─────────────────┘ └─────────────┘ │
└──────────────────────────────────────────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              │  H3 Studio（进阶，低频）     │
              │  http://127.0.0.1:3000    │
              │  多镜头分镜板 / 末帧接力     │
              └───────────────────────────┘
~~~

### 1.2 成本模型（重点）

| 环节 | 谁做 | 成本 |
|---|---|---|
| 提示词增强 | 官方 API（ComfyUI 里的 Context IR 节点） | **$0.02 / 次** |
| 本地生成 | 你的 Mac | **零边际成本** —— 想跑多少次都行 |
| 2K 再生成 | 官方 API | 按官方计费，只为最终成品付 |

**最优策略**：花 2 分钱让官方写好提示词 → 本地免费反复试 → 满意了才花钱做 2K。

## 2. 每次开机后的准备（1 分钟）

### 2.1 启动 ComfyUI

打开「终端」，粘贴：

~~~bash
cd $H3_ROOT
./start-comfyui
~~~

**你会看到**最后一行出现：

~~~
To see the GUI go to: http://127.0.0.1:8188
~~~

**不要关闭这个终端窗口** —— 关掉服务就停了。

### 2.2 打开网页

浏览器访问 **http://127.0.0.1:8188**

**你会看到**一个深色画布，中间有几个节点（默认工作流）。

### 2.3 检查是否正常

在浏览器地址栏把 URL 换成 `http://127.0.0.1:8188/api/userdata?dir=workflows&recurse=true`

**你会看到**（说明三张工作流都在）：

~~~
["h3-local-draft.json", "h3-local-quality.json", "h3-full-chain.json"]
~~~

> 如果显示 `Directory not found`，见第 8 章 Q1。

## 3. 实操演练（手把手）

> 每个演练都是从零到出片的完整流程。第一次用请从演练 1 开始。

### 🎬 演练 1：第一次出片（约 23 分钟）

**目标**：生成你的第一条带声音的视频。

---

**第 1 步 · 打开工作流**

1. 在 ComfyUI 页面**左上角**，点击 ☰ 形状的**侧栏图标**
2. 侧栏展开后，找到 **Workflows**（工作流）区域
3. 点击列表里的 **`h3-local-draft`**

**✅ 你会看到**：画布上出现两个节点，用一条线连着：

~~~
┌──────────────────────────┐
│  Wild H3 Text to Video   │
│  prompt: [A red fox...]  │──────┐
│  width: 864   height: 480│      │
└──────────────────────────┘      │
                                  ▼
                        ┌──────────────────┐
                        │   Save Video     │
                        │ h3-local-draft   │
                        └──────────────────┘
~~~

---

**第 2 步 · 改提示词**

1. 用鼠标**点击**左边节点里的 **`prompt`** 输入框（那一大段英文）
2. **全选** `Cmd+A` → **删除**
3. 输入你的描述，例如：

   ~~~
   A red fox walks through fresh snow in a pine forest. Medium tracking shot, natural winter light, realistic fur, soft footsteps and wind.
   ~~~

   > 中文也可以，但英文效果通常更稳。
   > 💡 更省事：用第 4 章的 Context IR 把中文想法变成专业提示词。

---

**第 3 步 · 检查参数**（一般不用改）

点击节点，确认这些值：

| 参数 | 应该是 |
|---|---|
| `width` | 864 |
| `height` | 480 |
| `seconds` | 5.17 |
| `steps` | 6 |
| `preset` | precise |
| `ssd_streaming` | **✅ 勾选状态** |

> ⚠️ **`ssd_streaming` 必须勾选**。这是 32GB 机器能跑的前提，取消勾选一定失败。

---

**第 4 步 · 开始生成**

1. 点击右侧或顶部的 **Run**（也可能显示为 **Queue Prompt**）
2. 或直接按 `Cmd + Enter`

**✅ 你会看到**：节点上出现**进度条**；**Queue** 面板显示 1 个任务；终端开始刷日志。

---

**第 5 步 · 等待**

**预计 23 分钟**。期间：

- ❌ 不要关终端窗口
- ❌ 不要让电脑睡眠
- ✅ 想看是否还活着：

~~~bash
ps -o etime=,time= -p $(pgrep -x h3 | head -1)
~~~

两个时间都在增长 = 正常工作中。

---

**第 6 步 · 看结果**

~~~bash
open $H3_ROOT/ComfyUI/output/
~~~

双击 mp4 播放 —— **带原生立体声**（对白、音效、环境音都是模型一起生成的）。

**🎉 演练 1 完成**。你已经会了 90% 的日常操作。

---

### 🔁 演练 2：快速迭代（2 分钟看构图）

**目标**：不花 23 分钟，先快速确认构图对不对。

在演练 1 基础上只改两个参数：

1. `seconds`：`5.17` → **`0.92`**
2. `width` / `height`：→ **512 / 512**
3. Run → 约 **2 分钟**出片

看着还行？再改回 `1344×768` + `5.17` 秒跑正式的。

> ⚠️ 0.92 秒的片子**不能送官方 2K**（帧数不足 107）。只用于本机预览。

### 🖼️ 演练 3：用一张图生成视频（图生视频）

**目标**：让一张静态照片动起来。

---

**第 1 步 · 加载工作流**

同演练 1，加载 **`h3-local-quality`**

---

**第 2 步 · 添加图片节点**

1. 在画布**空白处双击**
2. 搜索框输入 `load image`
3. 点击 **Load Image** 添加

**✅ 你会看到**：画布上多了一个 Load Image 节点。

---

**第 3 步 · 上传图片**

1. 在 **Load Image** 节点上点 **`choose file to upload`**
2. 选择图片 → 图片显示在节点上

---

**第 4 步 · 连线**

1. 找到 **Load Image** 节点右侧的 **IMAGE** 输出圆点
2. **按住鼠标左键**从圆点拖出一条线
3. 拖到 **Wild H3 Text to Video** 节点左侧的 **`first_frame`** 输入圆点
4. 松开

**✅ 你会看到**：两节点之间出现连线。

---

**第 5 步 · 写提示词**

描述**中间发生什么**，不用重复描述首帧画面：

~~~
The fox turns its head slowly toward the camera, snowflakes drifting past.
~~~

**第 6 步 · Run**

同演练 1。生成完成后，视频会从你上传的那张图开始动起来。

### ⚡ 演练 4：一句话出 2K 成片（全链路，约 100 分钟）

**目标**：只写一句中文，自动完成「增强提示词 → 本地生成 → 官方 2K」。

**成本**：$0.02（提示词增强）+ 官方 2K 费用。

---

**第 1 步 · 加载全链路工作流**

侧栏 → Workflows → 点击 **`h3-full-chain`**

**✅ 你会看到**四个节点连成一串：

~~~
┌──────────────┐   ┌──────────────────┐   ┌──────────────┐   ┌───────────┐
│ Context IR   │──▶│ Wild H3 Text to  │──▶│ Regenerate   │──▶│Save Video │
│ (提示词增强)  │   │ Video (本地生成)  │   │ to 2K (官方) │   │           │
│ prompt:      │   │ 1344×768 / 124帧  │   │ resolution:  │   │h3-2k-final│
│ [写中文想法]  │   │ 6步 / precise     │   │ 2K           │   │           │
└──────┬───────┘   └──────────────────┘   └──────────────┘   └───────────┘
       │                                                          ▲
       └──────────────────────────────────────────────────────────┘
         增强后的提示词同时喂给「本地生成」和「2K 节点」
~~~

---

**第 2 步 · 写中文想法**

1. 点击最左边的 **MiniMax H3 Context IR** 节点
2. 在 `prompt` 框里写一句话中文，例如：

   ~~~
   一只红狐狸在雪地里走过，镜头跟着它，冬天清晨的光线，能听到风声和踩雪的声音
   ~~~

3. （可选）`duration` = **5**（计划秒数，4–15）、`ratio` = **16:9**

---

**第 3 步 · 检查后两个节点的参数**

点击 **Wild H3 Text to Video**，确认：

| 参数 | 应该是 | 为什么 |
|---|---|---|
| `width` / `height` | **1344 / 768** | 2K 要求面积 ≥ 768×768 |
| `seconds` | **5.17** | 2K 要求帧数 107–362 步进 17 |
| `steps` | 6 | Turbo 折叠模型 |
| `preset` | precise | Turbo 必须 reuse=1 |
| `ssd_streaming` | ✅ 勾选 | 32GB 必须 |

点击 **Regenerate to 2K**，确认 `resolution` = **`2K`**。

> ⚠️ **不要改 Regenerate 节点的 prompt** —— 它已连到 Context IR 输出，改了会破坏「提示词必须与生成原片完全一致」的要求。

---

**第 4 步 · Run**

按 `Cmd + Enter`。

---

**第 5 步 · 观察四个阶段自动流转**

| 阶段 | Queue 里看到的 | 耗时 | 成本 |
|---|---|---|---|
| ① 提示词增强 | 节点 1 运行 | 1–3 分钟 | $0.02 |
| ② 本地生成 | 节点 2 运行 + 终端刷 h3 日志 | 约 92 分钟 | 免费 |
| ③ 官方 2K | 节点 3 运行 | 2–5 分钟 | 官方计费 |
| ④ 保存 | 节点 4 运行 | 秒级 | 免费 |

> 💡 **中途可以关浏览器页面吗？** 可以 —— 任务在服务端跑。但**不能关终端**。

---

**第 6 步 · 拿到 2K 成片**

~~~bash
open $H3_ROOT/ComfyUI/output/
~~~

文件名形如 `h3-2k-final_00001_.mp4`，规格 **2560×1440**。

**🎉 全链路完成** —— 你只写了一句中文。

## 4. 文生图操作（Z-Image）

> 让 Mac 自己画图 —— 出图、改图、给视频做首帧

### 4.1 六张文生图相关工作流

> **主力是 Turbo**。它又快又好（1.7 分钟/张），下面几张 Turbo 工作流覆盖了几乎全部需求。
> base 版留着做实验，日常不用管它。

| 工作流 | 模型 | 参数 | 实测耗时 | 用途 |
|---|---|---|---|---|
| `image-t2i-turbo` ⭐ | Turbo | 8步 / 1024² / **batch 4** | **7.1 分钟出 4 张** | **主力**：概念图、配图 |
| `image-keyframe-for-video` ⭐ | Turbo | 8步 / **1344×768** / **batch 4** | **6.9 分钟出 4 张** | **主力**：视频首帧 |
| `image-to-video` ⭐ | Turbo → Wild H3 | 8步 → 6步 | 约 2 分钟 + 92 分钟 | **主力**：图 → 视频 |
| `image-upscale-2k` ⭐ | RealESRGAN | 4x → 0.5x | **2 秒** | **主力**：配图放大到 2K |
| `image-upscale-2k-refine` | + Z-Image 精修 | 5步 / denoise 0.33 | 8 分钟 | 需要重绘细节时用 |
| `image-t2i-base` 🧪 | base | 25步 / **CFG2** / 1024² / batch 1 | 11.6 分钟出 1 张 | **实验档**（慢 6.6 倍，锐度不如 Turbo） |

**三句话记住**：

1. **要给视频做首帧，必须用 `image-keyframe-for-video`（1344×768）**，不能用方图。
2. **不知道用哪个，就用 `image-t2i-turbo`** —— 它适用于绝大多数场景。
3. **出好的图想放大，用 `image-upscale-2k`** —— 1024² → 2048²，只要 2 秒。

### 4.4 实测性能（本机真实数据）

| 配置 | 耗时 | 单张 |
|---|---|---|
| Turbo 1024² / 8步 / **batch 1** | **104.5s** | 1.7 分钟 |
| Turbo 1024² / 8步 / **batch 4** | **426.6s** | 1.8 分钟 |
| Turbo 1344×768 / 8步 / **batch 4** | **414.3s** | 1.7 分钟 |
| base 1024² / 25步 / CFG4 / **batch 1** | **696.1s** | 11.6 分钟 |
| 图 → 视频（出图 + 短视频） | **351s** | — |

**五条重要结论**：

1. **Turbo 是绝对主力** —— **105 秒/张**，比 base 快 **6.6 倍**，而且**锐度更好**。
   日常请一律用 Turbo。
2. **批量不省时间** —— batch 4 就是 batch 1 的 4 倍耗时，单张成本不变。
   批量的价值是"一次拿 4 个候选"，不是"更快"。
3. **Turbo 每步约 13 秒；base 每步约 26 秒**（CFG≠1 时每步要跑两次前向）。
4. **⚠️ 官方模板给 base 的 CFG=4 过高** —— 会导致背景糊成一片、毛发简化。
   **改成 CFG=2 后背景结构恢复**（本手册的 base 工作流已修正为 CFG2）。
5. **即便修正 CFG，base 的锐度仍不如 Turbo**，且慢 6.6 倍。
   所以 base 只作实验用途，**不要当作"更高质量"的选项**。

> 📌 **一句话**：官方的 "base 更精细、Turbo 更快" 在本机实测中**不成立** ——
> Turbo 在速度和质量上**同时胜出**。

### 4.5 batch_size 怎么调

在 **EmptySD3LatentImage** 节点上直接改数字：

| 值 | 效果 | 适合 |
|---|---|---|
| **1** | 1.7 分钟出 1 张 | 快速迭代，边看边改 |
| **2** | 3.5 分钟出 2 张 | 平衡 |
| **4** | 7 分钟出 4 张 | 一次挑个够 |

> 改完直接 Run，不用重启。

### 4.6 把配图放大到 2K

| 工作流 | 做法 | 耗时 | 锐度 |
|---|---|---|---|
| **`image-upscale-2k`** ⭐ | RealESRGAN 纯放大 | **2 秒** | **2.26× 原图** |
| `image-upscale-2k-refine` | 放大 + Z-Image 重绘精修 | 8 分钟 | 0.93× 原图 |

**1024×1024 进去，2048×2048 出来。**

#### 怎么用

1. 打开 **`image-upscale-2k`**
2. 在 **Load Image** 节点点 **choose file to upload**，选你的图
   （也可以直接把 `ComfyUI/output/` 里的图拖进去）
3. Run —— **2 秒**出结果

#### ⚠️ 一个反直觉的发现

官方模板里带了一个「精修」步骤（用 Z-Image 以 denoise 0.33 重绘一遍）。
**实测发现它会把放大器的成果抹掉**：

| 方案 | 拉普拉斯方差（越高越锐） |
|---|---|
| 原图 1024² | 131.9 |
| 纯 RealESRGAN | **298.0（2.26×）** ✅ |
| RealESRGAN + VAE 往返 | 273.2（2.07×） |
| **官方模板（含精修）** | **122.7（0.93×）** ❌ |

精修确实会「重绘」细节，但代价是把 RealESRGAN 补出来的高频细节重新磨平了。

**所以本手册把默认工作流改成纯放大**（又锐又快 238 倍）；
精修版单独留一张，只在你需要模型重新演绎细节时用。

## 5. 多镜头分镜（ComfyUI 原生）

> 做 3 个连贯镜头，自动末帧接力 + 一键拼接 —— **不需要 H3 Studio**

### 5.1 这是什么

`h3-storyboard-3shot` 把「多镜头叙事」搬进了 ComfyUI：

~~~
[结构化提示词1] ─▶ 镜头1 ─┬───────────────────────▶ SaveVideo (shot-1)
                          │
                          └─▶ H3 Get Last Frame ─┐
                                                  │ 首帧锚定
[结构化提示词2] ─▶ 镜头2 ◀────────────────────────┘
                    │     └───────────────────────▶ SaveVideo (shot-2)
                    │
                    └─▶ H3 Get Last Frame ─┐
                                            │ 首帧锚定
[结构化提示词3] ─▶ 镜头3 ◀──────────────────┘
                    └───────────────────────────▶ SaveVideo (shot-3)

镜头1 + 镜头2 + 镜头3 ─▶ Concatenate Video ─▶ SaveVideo (成片)
~~~

**你只需要填三个「结构化提示词」节点，点一次 Run。**

#### 两个专用节点

| 节点 | 作用 |
|---|---|
| **H3 Structured Prompt** | 把「场景 / 动作 / 镜头 / 风格 / 音效」五个框拼成一段提示词。分开填比写一大段更容易想清楚，留空的框自动跳过 |
| **H3 Get Last Frame** | 从视频取最后一帧。把上一个镜头的末帧接到下一个镜头的 `first_frame`，两镜就严丝合缝 |

> 这两个节点是本机自研的（`ComfyUI/custom_nodes/h3-toolkit/`，89 行）。
> 它们把工作流从 15 节点压缩到 **13 节点**，更重要的是让提示词**结构化**。

#### 镜头数是可配的

默认 3 镜。**增删 `scripts/gen_workflows.py` 里的 `STORYBOARD` 列表条目**，重新跑一次生成脚本即可：

~~~bash
cd $H3_ROOT
# 编辑 scripts/gen_workflows.py 里的 STORYBOARD 列表
./.venv/bin/python scripts/gen_workflows.py
cp workflows/*.json ComfyUI/user/default/workflows/
~~~

> 拼接用的 `ConcatenateVideo` 槽位会跟着镜头数自动调整。

### 5.2 耗时与参数

**实测速率：864×480 下约 12 秒/帧**（0.2 分钟/帧）。

| 镜头类型 | 帧数 | 时长 | 实测耗时 |
|---|---|---|---|
| 建立镜头 | **192** | 8.0 秒 | **约 41 分钟** |
| 普通镜头 | 124 | 5.17 秒 | 约 25 分钟 |

默认三镜（192 + 124 + 124 = 440 帧）**实测 91 分钟**。

> ⚙️ **要做成品画质**？把三个节点的 width/height 都改成 **1344×768**，
> 但耗时约为 864×480 的 2.4 倍 → 三镜要 **3.6 小时**。

**三次实测对比**：

| | 小参数验证 | 正式（3×124 帧） | **正式（192+124+124）** ⭐ |
|---|---|---|---|
| 单镜 | 512² / 22 帧 | 864×480 / 124 帧 | **864×480 / 192+124+124** |
| **总耗时** | 471 秒 | 4231 秒（70.5 分钟） | **5461 秒（91.0 分钟）** |
| 拼接帧数 | 66 = 22×3 ✅ | 372 = 124×3 ✅ | **440 = 192+124+124** ✅ |
| 成片时长 | 2.75 秒 | 15.5 秒 | **18.33 秒** |
| 末帧接力 | ✅ | ✅ 视觉无缝 | ✅ **视觉无缝** |

> **第三次跑的完整叙事弧**：大远景（横摇展示远山与脚印）→ 中景跟拍（狐狸变大、金色长影）
> → 特写（狐狸抬头仰望）。
> 第三镜的提示词要求"停下抬头、推近特写"，成片**完全照做** —— 说明接力没有干扰模型对提示词的执行。

#### 建立镜头为什么要 8 秒

124 帧（5.17 秒）对"大远景建立镜头"太短 —— 观众还没看清环境就切走了。
改成 192 帧（8 秒）后，镜头有足够时间横摇、让远山和脚印依次进入画面。

> 8.0 秒 = 192 帧，**同时满足** h3.c 的 `17k+5` 和官方 2K 的 `107+17k` 两个网格。

### 5.4 常见问题

**Q：想要 4 个或 5 个镜头？**

目前工作流固定 3 镜。可以：
- 拆成两批跑（3 镜 + 2 镜），再用 `ConcatenateVideo` 拼

要。ComfyUI 的图是原子执行的。这也是 H3 Studio 断点续跑的价值所在。

./h3gen "$(cat /tmp/prompt.txt)" quality
./comfy-2k h3.c/outputs/h3-quality-*.mp4 "$(cat /tmp/prompt.txt)"
~~~

## 9. 参数与硬约束

### 9.1 分辨率

- 宽高**必须是 32 的倍数**
- 面积 ≤ **768×1344 = 1032192**
- 原生 16:9 = **1344×768**

### 9.2 帧数（两个不同的网格！）

| 用途 | 网格 | 合法值 |
|---|---|---|
| **本地生成**（h3.c） | `17k+5` | 5, 22, 39, 56, 73, 90, **107**, **124**, 141, …, 243 |
| **官方 2K 再生成** | `107+17k`，范围 107–362 | **107**, **124**, 141, 158, …, 362 |

> ⚠️ **124 帧是两者唯一在常用区间的交集** → 所以 `seconds` 统一填 **5.17**。

### 9.3 2K 再生成的四条硬性要求

1. 输入必须是**未修改**的原始成片
2. 帧数 **107–362、步进 17**
3. 面积 **≥ 768×768 = 589824 像素**（**864×480 也不够**）
4. 提示词必须与生成原片时**完全一致**（全链路工作流已用连线保证）

## 10. 常见问题（FAQ）

### Q1：侧栏里看不到三张工作流

~~~bash
cd $H3_ROOT
ls ComfyUI/user/default/workflows/
~~~

- 目录为空 → 重新部署：`./.venv/bin/python scripts/gen_workflows.py && cp workflows/*.json ComfyUI/user/default/workflows/`
- 文件在但界面看不到 → 点侧栏刷新按钮，或重启 ComfyUI

### Q2：网页打不开 / 返回 000

~~~bash
cd $H3_ROOT
pkill -f "ComfyUI/main.py"; sleep 2; ./start-comfyui
# H3 Studio：
pkill -f "server/main.py"; pkill -f vite; ./h3studio
~~~

### Q3：提示端口被占用

~~~bash
lsof -nP -iTCP:8188 -sTCP:LISTEN     # 找出占用进程的 PID
kill -9 <PID>
./start-comfyui
~~~

### Q4：生成很慢，是不是卡住了？

~~~bash
ps -o etime=,time=,rss= -p $(pgrep -x h3 | head -1)
~~~

- `etime`（已运行时间）在增长 = 任务在进行
- `time`（CPU 时间）也在缓慢增长 = 正在计算
- 参考：864×480/5秒 ≈ 23 分钟；1344×768/5秒 ≈ 92 分钟

### Q5：节点报 `invalid params, base_video area ... below min 589824`

2K 节点的输入分辨率太小。把 `width` / `height` 改成 **1344 / 768**。

### Q6：节点报 `length is 107 to 362 frames in steps of 17`

帧数不合规。把 `seconds` 改成 **5.17**（=124 帧）。

### Q7：`api.comfy.org` 连接报错 / Retrying

DNS 偶发挂起，**不是故障**。ComfyUI 会自动重试 3 次，通常第 3 次成功，单次多等约 2 分钟。看到 `Retrying` 不用管。

### Q8：内存不足 / 系统变卡

- 确认 `ssd_streaming` **已勾选**
- 关闭浏览器等其他大内存程序
- 降低分辨率或改用 `h3-local-draft`

### Q9：想用原始权重（不用 Turbo）

把 `steps` 改成 20、`preset` 改成 `balanced`，并把 `model_dir` 改成 `$H3_ROOT/models/MiniMax-H3`。
